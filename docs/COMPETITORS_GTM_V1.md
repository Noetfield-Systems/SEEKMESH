## Real wedge, in one sentence
**Proof-backed project discovery operated by AI agents and humans, presented as a premium playable world, and monetized by verified contributions and native wallet settlement.**

The discovery graph is the primary utility, the Realm/guilds are a retention and organization layer, and crypto settlement is a verifiable utility rail, **not the product itself**.

## User reasons to return
- **Explorer**: find credible, fresh tools, real signals and opportunities; develop a named explorer profile and meaningful progress.
- **Builder**: own an accurate project profile, gain discoverability, correct outdated data, recruit guild collaborators, purchase transparent discovery tasks (once funded).
- **Curator**: establish verified subject expertise; manage trusted category sources; use earned in-app visibility; participate in externally funded missions once available.
- **Guild**: achieve a shared meaningful exploration goal, see accepted evidence and visible group contribution.
- **Agent developer**: consume a typed, provenance-linked index and eventually pay per successful API result.
- **Sponsor**: fund useful third-party discovery/research and monitor verified completion receipts, not generic impressions or fake engagement.

## GTM strategy — narrow before broad
**First beachhead:** agent infrastructure, MCP ecosystems, EVM developer projects and real Web3 builder guilds. Do NOT attempt to map every crypto token, meme asset and metaverse at launch. Start with a small corpus of sources whose correctness can be checked and improved.

### Wave A: 7-day first real network (targets, NOT achieved metrics)
- Verify production sign-up, mission completion, project submission, wallet-binding, search and guild creation with real participants.
- Invite 20 known maintainers with individual evidence-aware messages, aiming for 10 genuine builder listings (not copied seed entries).
- Invite 5 community curators and 3 guild founders to run a small source verification sprint.
- Instrument source click-through and recurring contributors; report actual values, including zero.
- Put documented token and reward terms in public Whitepaper: no monetary entitlements until funded.

### Wave B: 30-day product and partner traction
- Target 100 source-linked entries with at least 50% recently checked, 30 qualified real contributor accounts, 10 real guild posts with moderation, and 20 accepted useful source submissions.
- Add clear source provenance, recrawl timestamps, public submission status and project owner badges.
- Recruit 3 protocol or infrastructure teams for **funded discovery experiments**, initially with documented USDC budgets and disclosed terms; do not promise payment if escrow isn't deployed.
- Promote through GitHub/README links, independent dev communities, original fantasy art trailers and properly disclosed builder partnerships. No mass unsolicited DMs or automated karma manipulation.

### Wave C: 90-day proof of value
- First real paid stablecoin mission funded and settled once with onchain tx receipt, cancellation/refund test.
- First paid x402 API request/response with proof of verified payment and receipt.
- Demonstrate healthy unit economics: true fees collected versus direct processing/reward expense.
- Scale workers based on source freshness and approved discoveries per dollar, not shard count.
- Public token roadmap only after protocol and economic feedback; token launch is an option, not proof of success.

## Product channels by persona
**Developer distribution:** GitHub open source issue/pull proposals, MCP registry listing where eligible, agent tool maintainers, technical docs, reciprocal integration examples.
**Web3-native community:** Farcaster project builders, selected guild operators, developer hackathons, wallet/chain ecosystem communities, carefully moderated Discord/Telegram groups.
**Product-based loops:** source-linked project profile and badge; personalized invite link qualified only when an accepted contribution exists; reproducible guild expeditions; public verified source revision.
**Discovery content:** category maps of useful projects, high-quality source provenance comparisons and public micro-reports; make interesting screenshots from REAL data, not invented market performance.

## North star and guardrails
North Star: weekly **verified useful discovery outcomes** (accepted verified source, verified project match, useful external source click, completed funded task, or paid API result). Avoid adding unlike events into a financially weighted score without separate breakdown.

Track activation (new accounts that perform one useful action within first day), D7 human retention (anonymous cookies cannot be claimed as unique humans), accepted source contribution rate, recrawl age, guild active contribution, API result use, paid USDC transaction success, sponsor repeat funding, cost per verified source and gross contribution margin.
Detect Sybil clusters, copy/paste submissions, repeated empty searches, single project self-boost and spammed guild messages. Real user revenue and funded user rewards must be verified via settlement data.
